### 1. System Overview

**CounselMate** is a **Web-based Guidance Monitoring and Record-Keeping System** designed for university guidance counselors. It manages student policy violation records through admission slips — from issuance, through form completion with AI-validated violation descriptions, to approval — with analytics dashboards and exportable reports.

### 6. Middleware Stack

1. **CORS** — Origins restricted to `CORS_ORIGIN` env var, credentials enabled
2. **`express.json()`** — Body parser
3. **`validateInput`** (validateInput.js) — Global input length validation:
   - Default max: **32 characters** for all string fields
   - Route-specific overrides:
     - `PUT /admission-slips/:id/complete` → `description`, `teacher_comments`, `remarks`: 500 chars
     - `POST /admission-slips/validate-violation` → `description`: 500 chars
     - Auth endpoints → capped at 32 chars
   - Recursively checks `req.body`, `req.query`, `req.params`
4. **Rate Limiter** (rateLimiter.js):
   - In-memory `Map`-based store (keyed by IP + label + email)
   - Max attempts: **3** (configurable via `MAX_ATTEMPTS`)
   - Escalating lockout durations: **3, 5, 7, 9, 12, 15 minutes** (configurable per-endpoint via env vars)
   - Window: **15 minutes** (configurable via `RATE_LIMIT_WINDOW_MINUTES`)
   - Returns `429 Too Many Requests` with `Retry-After` header and `retryAfterMs` in body
5. **Auth Middleware** (auth.js) — JWT Bearer token verification + role-based authorization (defined but not currently applied to routes in the demo)

### 7. AI/LLM Integration — Violation Matcher

Defined in violationMatcher.js:

- **Primary:** Ollama local LLM (model: `dolphin3`, configurable via `OLLAMA_MODEL`)
  - Endpoint: `POST /api/generate` on `http://localhost:11434`
  - Prompt strategy: Strict yes/no classification — asks LLM if description **confirms** the student committed the violation
  - Handles negation, questions, and vague descriptions as MISMATCH
  - Temperature: `0.1`, max tokens: `3` (forces single-word response)
  - Available check: `GET /api/tags` to verify Ollama is running

- **Fallback** (when Ollama is unavailable): Keyword-based matching
  - Predefined keyword dictionaries for 8 violation types: `TARDINESS`, `TRUANCY`, `DISRESPECT`, `BULLYING`, `CHEATING`, `FIGHTING`, `VANDALISM`, `DRESSCODE`
  - Checks exact type name in description, then related keywords
  - Returns lower confidence scores (0.75–0.85) compared to LLM (0.9–0.95)

**Integration points:**
- `POST /api/admission-slips/validate-violation` — standalone validation endpoint
- `PUT /api/admission-slips/:id/complete` — validates before saving the form

### 13. Notable Technical Patterns

1. **Context-driven state:** Centralized slip state (`SlipsContext`) ensures all components reflect real-time changes without prop drilling
2. **Debounced auto-verification:** Student name verification fires with a 600ms debounce as user types, using PostgreSQL `~*` regex with `\m...\M` word boundary matching
3. **AI-first with fallback:** Violation validation tries LLM first, falls back to keyword matching if Ollama is unavailable — ensures the system works offline
4. **Escalating rate limiting:** Progressive lockout durations (3→5→7→9→12→15 min) discourage brute force without permanently locking out legitimate users
5. **Server-rendered print page:** Print admission slip is a full HTML page rendered server-side with print-optimized CSS, auto-triggering `window.print()` on load
6. **Pure SVG charts:** Analytics visualizations built with raw SVG elements and CSS transitions — no charting library dependency on the frontend
